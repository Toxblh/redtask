# RedTask — применённые правила Apple HIG и App Store Review Guidelines

Источник: developer.apple.com/design/human-interface-guidelines (страницы tab-bars, sidebars,
split-views, lists-and-tables, sheets, context-menus, search-fields, notifications,
managing-notifications, onboarding, accessibility, layout, materials, privacy) и
App Store Review Guidelines (2.1, 2.3, 4.2, 5.1.1, 5.1.2), документация Privacy Manifest и Export Compliance.
Ниже — только то, что влияет на RedTask, и как именно это сделано.

## Навигация
- **Tab bar — для навигации, не для действий.** Пять разделов: Мои, Слежу, Избранное, Проекты, Поиск.
  «Новая задача», колокольчик, настройки — кнопки тулбара, не вкладки.
- **Не больше пяти вкладок, без More.** Поиск — отдельная вкладка с ролью `.search`, iOS 26 ставит её
  в конец таб-бара отдельной кнопкой.
- **Вкладки не прячутся и не выключаются.** Пустой раздел (Избранное без звёзд) объясняет, почему пусто
  (`ContentUnavailableView`), вкладка остаётся.
- **Подписи в одно слово + SF Symbols** (filled-варианты выбирает система).
- **Бейдж — только для критичного.** Бейдж на колокольчике и на иконке приложения = число
  непрочитанных уведомлений, и ничего больше; обнуляется при открытии истории.
- **iPad: tab bar, превращаемый в сайдбар** (`.tabViewStyle(.sidebarAdaptable)`), а не самописный
  сайдбар. Внутри раздела — `NavigationSplitView` (список ↔ задача), выбранная строка подсвечивается
  постоянно, деталь при запуске — подсказка «Выберите задачу».
- **Модальное поверх таб-бара — только временное** (листы, вход, капча).

## Списки
- Системный `List` (`.plain` для лент задач, `.insetGrouped` для формы и настроек).
- Короткие строки: номер, тема (2 строки), проект/статус/исполнитель вторичным цветом; подробности — в детали.
- **Swipe actions** на задаче: «Избранное» (ведущий край) и «Взять себе» (замыкающий), всё дублируется
  в `contextMenu` и на экране задачи — жест не единственный путь (Accessibility → Mobility).
- **Контекстное меню** везде одинаково: задача, комментарий, вложение, связь, запись времени, уведомление.
  Не больше трёх групп, системные иконки для Copy (`doc.on.doc`), Share (`square.and.arrow.up`),
  Delete (`trash`, role `.destructive`). Подменю — максимум один уровень.
- Длинные списки — подгрузка по мере прокрутки, `.refreshable` для pull-to-refresh.

## Поиск
- Поиск-вкладка: при входе поле в фокусе на iPhone; на iPad с экранной клавиатурой — без автофокуса.
- Поиск начинается при вводе (с задержкой 400 мс), `#123` открывает задачу по номеру.
- Внутри списков — `.searchable` для фильтра текущего списка (поиск по теме на сервере).
- Фильтр Открытые/Закрытые/Все — сегментированный `Picker` под заголовком (скоуп списка).

## Листы (sheets)
- Один лист за раз; новый лист — только после закрытия предыдущего.
- Cancel — ведущий край тулбара, Done/Сохранить/Отправить — замыкающий.
- Короткие выборы (статус, приоритет, готовность) — `.presentationDetents([.medium, .large])` с grabber;
  составление комментария и правка задачи — только `.large` (как compose в Mail).
- Свайп вниз закрывает лист; при несохранённом вводе — `interactiveDismissDisabled` + подтверждение
  «Отменить изменения».
- Ошибка — `alert`, а не уведомление (Notifications → «Use an alert — not a notification — to display an error»).

## Уведомления
- **Разрешение — в контексте**, не при запуске. Отказ → ссылка в Настройки системы.
- Заголовок — `#номер тема`, тело — «Автор: событие», подзаголовок — проект. Без имени приложения.
- `threadIdentifier` = номер задачи: события одной задачи складываются в стопку.
- Одно уведомление на событие, без повторов: дедуп по ключу события (как в Android).
- Действие «Не уведомлять по задаче» (не destructive, с иконкой `bell.slash`); действия «просто открыть» нет —
  тап по уведомлению и так открывает задачу на нужном комментарии.
- `interruptionLevel`: группы «Мне» и «Обсуждение» (назначено, упоминание, комментарий) — `.active` со звуком, ход работы/сроки/проекты — `.passive` без звука; Time Sensitive не используем.
- Разрешение при входе — тихое (`.provisional`): системного вопроса нет, уведомления идут в Центр уведомлений; в Настройках — кнопка «Показывать уведомления баннерами», которая и задаёт системный вопрос.
- Приложение на экране — баннер не нужен: бейдж колокольчика растёт, запись появляется в истории.
- В приложении есть экран настроек уведомлений (категории, источники, отключённые задачи и проекты).
- Фоновая проверка честно ограничена iOS: `BGAppRefreshTask` запускается по решению системы;
  в настройках это написано прямо, плюс проверка при каждом возврате в приложение.

## Онбординг и вход
- Онбординга нет: первый экран — вход. «Войти через сайт» основной, ручной ключ — запасной путь.
- Никаких лицензий/дисклеймеров на входе.

## Доступность
- Только системные текстовые стили (`.body`, `.headline`, `.caption`…) — Dynamic Type вплоть до AX5;
  строки списков переходят в вертикальную раскладку на accessibility-размерах.
- Системные цвета (`.primary`, `.secondary`, `.tint`, `Color(.secondarySystemBackground)`) — светлая/тёмная
  тема и Increase Contrast бесплатно.
- Информация не только цветом: просрочка — красный + иконка `exclamationmark.circle`, приватность —
  иконка замка + подпись.
- VoiceOver: у иконок-кнопок `accessibilityLabel`, у строки задачи — единая подпись
  (`accessibilityElement(children: .combine)`), аватары — подпись именем, декоративное скрыто.
- Цели касания ≥ 44 pt (системные кнопки; свои — `.contentShape` + `frame(minHeight: 44)`).
- Жесты дублируются кнопками (свайп ↔ контекстное меню ↔ кнопки на экране задачи).

## Liquid Glass / материалы (iOS 26+)
- Стекло — только у системных навбара/таб-бара/тулбаров/листов, которые получают его автоматически.
  В контенте (карточки, цитаты, код) стекла нет — обычные `secondarySystemBackground`.
- Никаких своих фонов под тулбарами; scroll edge effect — системный.
- Акцентный цвет один (красный «Redmine»), таб-бар монохромный по умолчанию.

## Layout
- Раскладка по size class, не по типу устройства: компактная ширина — стек, регулярная — split view.
- Ширина текста детали задачи ограничена читабельной (`.frame(maxWidth: 820)`) на широком iPad.
- Не больше 2–3 кнопок в ряд; остальные действия — меню «…» в тулбаре.

## Приватность и App Store Review
- **2.1 / 5.1.1:** приложение — клиент чужого сервера; учётных записей мы не создаём, поэтому
  удаление аккаунта (5.1.1(v)) не требуется — есть «Выйти», стирающий ключ из Keychain и все кэши.
  Для ревью нужен демо-доступ (тестовый Redmine и ключ) — в чеклисте.
- **Ключ — только в Keychain** (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, нужен фоновому опросу).
  Никогда в UserDefaults/файлах.
- Разрешения запрашиваются по месту: фото — системный PhotosPicker (без разрешения на всю библиотеку,
  `NSPhotoLibraryUsageDescription` не нужен), файлы — `fileImporter`, уведомления — в контексте.
- **Privacy Manifest** `PrivacyInfo.xcprivacy`: трекинга нет, сбор данных — нет (данные идут только на
  сервер пользователя, разработчику ничего не уходит); Required Reason API — `UserDefaults` (CA92.1).
- **ITSAppUsesNonExemptEncryption = NO**: только HTTPS системного URLSession (освобождено).
- Нет сторонних SDK, аналитики и рекламы.

## Сверка с HIG 30 октября 2026 (iOS 26.5 / 27.0)

Страницы перечитаны с developer.apple.com (JSON страниц HIG): segmented-controls, toolbars (с июня 2025 сюда
влита страница navigation-bars, отдельной больше нет), menus, context-menus, sidebars, split-views, tab-bars,
lists-and-tables, sheets, search-fields, notifications, pop-up-buttons, pull-down-buttons. Новое с прошлой сверки:

- **Sheets (24 марта 2026, «Updated guidance for button placement»):** «Provide an alternative to the Done
  button. If you provide a Done button, always pair it with a Cancel button … or a Back button». Cancel/Close —
  ведущий край, Done — замыкающий. → Листы только для просмотра (колокольчик, настройки, профиль, «Выделить
  текст») закрываются системной кнопкой Close (`Button(role: .close)`, ✕ слева), а не одиноким «Готово».
  Toolbars: «Use the standard Back and Close buttons … Prefer the standard symbols». Меню вида колокольчика
  переехало направо (`.primaryAction`), чтобы слева была только ✕.
- **Menus (8 июня 2026, иконки пунктов):** «Use menu item icons sparingly and with purpose» и «provide icons for
  all menu items in a group, or none of them». Наши меню (комментарий, задача, проект, разделы проекта) — с
  иконками у всех пунктов группы; стандартные символы Copy/Share/Delete.
- **Tab bars (8 июня 2026, терминология), Sidebars (8 июня 2026):** без изменений для нас — таб-бар
  `.sidebarAdaptable`, пять вкладок, поиск — отдельная вкладка в конце.
- **Search fields (8 июня 2026, «search as a tab in iOS»):** поиск-вкладка в виде кнопки — «brings focus to the
  search field and displays the keyboard … ideal when you want search to resolve quickly». Так и есть.
  Inline-поиск в списке: «position an inline search field above the list it searches». На экране проекта
  поле «Искать в этом списке» теперь стоит над фильтром Открытые/Закрытые/Все только в разделе «Задачи»,
  а не над переключателем разделов (раньше казалось, что ищет по всему проекту).
- **Toolbars (16 декабря 2025, Liquid Glass):** «Minimize the number of groups … aim for a maximum of three»,
  «keep the title under 15 characters», «Next to the title, the toolbar can include a document menu that contains
  … commands that affect the document as a whole». Заголовок с меню у нас — как раз это место.

### Разделы проекта: меню заголовка вместо сегментов
Было: сегменты «Задачи · Обзор · Вехи · Вики · Файлы» под навбаром. На iPad в средней колонке подписи
обрезались («Over…», «Versi…», по-русски «Зад…», «Фай…»), на iPhone стояли две полосы сегментов подряд
(разделы + Открытые/Закрытые/Все), а поле поиска задач — над обеими.

Почему так нельзя по HIG:
- Segmented controls: «Limit the number of segments … no more than about five segments on iPhone»; «As much as
  possible, use content with a similar size in each segment» — пять подписей разной длины, по-русски длиннее,
  в колонке 320 pt не помещаются; обрезанный сегмент — не читаемая подпись.
- Segmented controls → iOS: «Consider a segmented control to switch between closely related subviews» — это
  вторая полоса (Открытые/Закрытые/Все — одно и то же представление списка), а разделы проекта — разные экраны.
- Toolbars → Item groupings: рядом с заголовком — «document menu that contains … commands that affect the
  document as a whole»; Pop-up buttons: «Use a pop-up button to present a flat list of mutually exclusive
  options … Consider using a pop-up button when space is limited and you don't need to display all options all
  the time».

Стало: `toolbarTitleMenu` с `Picker` разделов (иконка + название у каждого пункта, галочка у текущего) —
заголовок «Мобильное приложение ▾», под ним подзаголовок с текущим разделом (`navigationSubtitle`, iOS 26).
Меню — плоский список взаимоисключающих вариантов, подписи никогда не обрезаются (меню само по ширине),
одна строка сегментов на экране — только фильтр статуса задач. Скрытые модули (выключены или 403) в меню
не попадают, как и раньше не попадали в сегменты. iOS 18: подзаголовка нет, раздел виден галочкой в меню.

### Статус задачи всегда цветной (spec 0)
Везде, где виден статус, он окрашен по виду (`IssueStatus.kind` → `statusTint`): капсула `StatusPill`
в строках, шапке, на доске; цветной текст в подзадачах и связях; цветная точка в меню и пикерах смены статуса
(в системное меню цвет SwiftUI не доходит — картинка `alwaysOriginal`); оба значения в записи
«Статус: было → стало»; капсула в выдаче поиска (статус разбирается из заголовка search.json). Цвет не
единственный признак: название статуса написано всегда, закрытые ещё и зачёркнуты и приглушены.
